# Port 26.1.2 -> 26.2 audit — breaking changes found

Status: compile-probe done (scratch bump + revert, no code changes committed
from this probe). See sibling design doc for context/decisions.

## Method

Scratch-bumped `gradle.properties` to `minecraft_version=26.2` /
`fabric_api_version=0.158.0+26.2` (latest available on maven.fabricmc.net as
of 2026-08-20), ran `compileJava`, captured every error, reverted the bump.
loader_version left at 0.19.3 -- untested whether a newer loader is required,
worth checking in the fix phase if loom itself complains.

## Result: BUILD FAILED, 32 errors, all "cannot find symbol" / "package does
not exist" -- no behavior-only risks surfaced yet since it never got past
compile. All are real API removals/renames, confirmed against the actual
downloaded 26.2 jar (`.gradle/loom-cache/minecraftMaven/.../26.2/...jar`):
none of the missing class names (`MultiBufferSource`, `Tesselator`,
`DestFactor`, `SourceFactor`, `OutlineBufferSource`, `TextureFormat` in its
old package, `ServerboundSpectateEntityPacket`) exist ANYWHERE in the jar
under any package -- not moved-and-renamed-findable-by-grep, genuinely gone
or restructured beyond a simple import fix. Replacement types were NOT
chased down this session (would need `genSources`/decompile, a separate
multi-minute step) -- that's fix-phase work, listed as "TBD" below.

## Breaking changes by symbol

### `net.minecraft.client.renderer.MultiBufferSource` -- REMOVED
Affected files (7): `TextRendererMixin.java`, `LogoutSpotModule.java`,
`NameTagsModule.java`, `Renderer3D.java` (import + `renderItem(...,
MultiBufferSource.BufferSource vertexConsumers)` param type),
`KillEffectMemeRenderer.java`, `skia/AbstractSkiaPipRenderer.java` (import +
constructor param), `skia/MusicHudPipRenderer.java` (import + constructor
param).
Replacement: TBD -- likely folded into a different vertex-consumer
abstraction under the GpuDevice model. Check what
`net.minecraft.client.renderer.LevelRenderer`/`EntityRenderDispatcher` now
take as their buffer-source parameter type in 26.2 decompiled source.
Severity: compile-blocking, touches real (non-Skia) rendering --
`TextRendererMixin`, `LogoutSpotModule`, `NameTagsModule` are NOT part of the
Skia comment-out list, must be fixed for real.

### `com.mojang.blaze3d.vertex.Tesselator` -- REMOVED
Affected files (3): `EspShader.java`, `Renderer3D.java`, `Renderer2D.java`.
Replacement: TBD. Was Mojang's immediate-mode vertex buffer builder --
almost certainly replaced by something in the GpuDevice/BufferBuilder
pipeline given the Vulkan backend needs command-buffer-friendly building,
not a singleton tesselator. High-priority to resolve since Renderer2D/3D are
this mod's core drawing utilities (ESP boxes, HUD, everything visual routes
through them).

### `com.mojang.blaze3d.platform.DestFactor` / `SourceFactor` -- REMOVED
Affected file: `Renderer3D.java` (2 imports).
Replacement: TBD -- blend-factor enums, likely relocated under a
`com.mojang.blaze3d.pipeline`/state-object package given the new backend
abstraction typically bundles blend state into a pipeline descriptor rather
than loose GL-style enum constants.

### `net.minecraft.client.renderer.blockentity.OutlineBufferSource` -- REMOVED
Affected file: `OutlineBufferSourceMixin.java` (the whole mixin target class
is gone).
Severity: HIGH -- this is the Chams-style Fill/Outline mechanism's mixin
target (per session memory `reference_shaders_hands_26_1_2.md`). If this
class is genuinely gone (not renamed), the entire outline-render approach
documented in that reference needs re-deriving for 26.2, not just a
method-signature patch. Flag for careful attention in fix phase -- check
whether outline rendering moved to a GpuDevice-level post-effect instead of
a buffer-source subclass.

### `com.mojang.blaze3d.textures.TextureFormat` -- REMOVED (from that package)
Affected file: `skia/LiquidGlassHud.java` -- part of the Skia block being
commented out entirely, not otherwise urgent to chase down. Note only in
case `TextureFormat` (or its replacement) is needed elsewhere later.

### `net.minecraft.network.protocol.game.ServerboundSpectateEntityPacket` -- REMOVED
Affected files (3): `PbPasswordHandler.java`, `PbPlayHandler.java`,
`PbWaitingHandler.java` -- all in `eu.client.pingbypass.handler`, the
PingBypass proxy packet-forwarding layer (not render-related at all --
protocol packet class renamed/restructured independent of the Vulkan
backend work, just surfaced by the same compile pass).
Replacement: TBD -- check if spectate-entity was merged into a different
packet or renamed (e.g. `ServerboundPlayerCommandPacket` sub-action, or a
straight rename). Low render-risk, but blocks compile just the same --
must be fixed in the same pass regardless of Vulkan scope.
