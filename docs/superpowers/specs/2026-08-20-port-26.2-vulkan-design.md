# Port 26.1.2 -> 26.2 (Vulkan backend compat) — design

Status: approved, audit phase about to start.

## Goal

Get pingbypass-main compiling and running correctly on Minecraft 26.2, under
Mojang's new Vulkan render backend (`Prefer Vulkan` / `Default` graphics API
option) as well as `Prefer OpenGL`. Scope: render-path compat, not new
features.

## Background / key facts (verified this session)

- 26.2 has a Fabric loader/loom release available (user-confirmed).
- 26.2's graphics API setting has 3 modes: Default (auto-pick), Prefer
  Vulkan, Prefer OpenGL. Crash-safety auto-downgrades (Vulkan crash -> Default
  -> Prefer OpenGL) on next launch. Sources: minecraft.net 26.2 snapshot-1
  notes, minecraft.wiki.
- Both backends sit behind the SAME Mojang `GpuDevice`/`RenderSystem`
  abstraction (already present since 26.1.2) -- mixins that go through this
  abstraction should be backend-agnostic already. The real risk is code that
  bypasses it with raw OpenGL calls.
- **Confirmed real risk found this session**: the Skia/Skija blur pipeline
  (`src/main/java/eu/client/utils/graphics/skia/`: `SkiaGlState.java`,
  `SkijaBackdropBlur.java`, `AbstractSkiaPipRenderer.java`,
  `LiquidGlassHud.java`, `MusicHudPipRenderer.java`) calls
  `DirectContext.makeGL()` / `BackendRenderTarget.makeGL()` -- hard-requires
  a live OpenGL context. Under Vulkan there is no GL context; these calls
  would fail/crash. This affects LiquidGlassHud, MusicHudPipRenderer, and
  backdrop blur effects specifically.
- 23 mixin files touch rendering and are the audit surface (list below).

## Decisions made

1. **Skia/Skija blur pipeline: comment out entirely for now** (user's
   decision, not runtime backend-detection, not a Vulkan port of Skija).
   Revisit later if blur effects are wanted back -- would need
   `DirectContext.makeVulkan()` with real `VkInstance`/`VkDevice`/`VkQueue`
   handles reflected out of Mojang's internal Vulkan backend, which is a
   separate, higher-risk sub-project.
2. **Port method: audit-first**, not bump-and-fix-compiler-errors. Reasoning
   given: know the risk list before touching real code.

## Audit process (this phase)

1. On a scratch/throwaway basis (do not commit the version bump to the real
   branch), bump `minecraft_version=26.2` in `gradle.properties`, run loom to
   let it genSources -- produces a fresh decompile to diff against
   `.mcref/src` (currently 26.1.2).
2. Diff each of the 23 render mixin targets (list below) plus `build.gradle`
   dependency versions against the 26.2 decompile. Record, per file:
   compile-error-certain / behavior-risk-only / unknown-needs-runtime-test.
3. Revert the scratch version bump. Audit produces a document, not code
   changes.
